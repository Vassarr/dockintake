Custom sites range from "I have a developer on speed dial" to "I built it myself with HTML and CSS three years ago." Here's how we handle each:

Path A · Webhook drop-in
One-line code addition
If you (or your developer) can access the form's submit handler, we provide a single endpoint URL to add. Takes about 60 seconds of code change.
Path B · Replacement form
Drop-in form embed
We provide a small embed snippet that replaces your existing form. Same look, instant connection to alerts, no backend changes needed on your end.
Path C · Landing page
We build a fresh page
If your site is hard to modify or you'd rather not touch it, we build a dedicated landing page (hosted by us) that handles everything. Great for running paid ads to.
Path D · Direct integration
Work with your developer
If you have a developer, we can talk to them directly. We provide the spec, they wire it up, we test it together. Cleanest long-term solution.
Not sure which fits? Reply with your site URL and a quick description of how it was built. We'll recommend the best path within a few hours.
Before you start

What you'll need on hand.

  • Your website URL
  • The phone number where you want SMS alerts to land

  • Access to your site's source files or developer contact info — whichever applies
If you're going with Path A

What the code addition looks like.

For Path A (the one-line code addition), we send you or your developer a webhook URL that the form should POST submissions to. Here's a simplified example of what that looks like in practice:

// Add this to your form's submit handler: fetch('https://hooks.dockintake.com/your-unique-id', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ name: formData.name, phone: formData.phone, email: formData.email, message: formData.message }) });
You don't need to write this yourself. If you have a developer, we send them this directly. If you don't, we recommend Path B (embed) or Path C (landing page) — both are zero-code on your end.

Common questions

Just in case.

I don't have a developer. Can I still do this?
Yes. Path B (embed) or Path C (we build you a landing page) both require zero technical work on your end. Mention this when you reply and we'll go straight to one of those.
Will this slow down my custom site?
No. The webhook fires asynchronously after form submission — your site's performance is unchanged.
My site is hosted somewhere weird (CodePen, GitHub Pages, a server I built myself). Does that matter?
Not really. As long as your form submits somewhere we can intercept (or we can replace it with our embed), we can wire up alerts regardless of where the site is hosted.
My developer left and I can't reach them. Now what?
This is more common than you'd think. Path C (we build you a landing page) is usually the cleanest move in that scenario — fresh page, full control, no dependence on the old developer.
Can I cancel later?
Yes. Depending on the path, cancellation is either removing the webhook line of code, removing the embed snippet, or simply letting the hosted landing page expire. No long-term contract — cancel anytime.
